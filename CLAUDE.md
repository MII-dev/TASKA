# TASKA

Персональний таск-менеджер на Google Apps Script. Один користувач, щоденне
використання, переважно з телефона. Мова інтерфейсу, назв колонок і промптів —
українська; коментарі в коді англійською.

Структуру файлів і команди деплою описує [README.md](README.md). Тут — те, чого
з коду не видно.

## Чого не видно з коду

**Apps Script склеює всі `.gs` в одну область видимості.** Поділ на файли суто
організаційний: функція з `Tasks.gs` викликається з `Calendar.gs` без імпортів.
Тому спільні хелпери (`buildSheetRow`, `withSheetLock`, `toCalendarDateKey`)
живуть там, де їх основний споживач, і це нормально.

**Фронтенд збирається з партіалів.** Тільки `index.html` сканується на
`<? ?>`-скриплети; решта вставляється як є через `include()`. Збірки немає,
фреймворку немає, npm-залежностей на фронті немає — весь клієнтський JS лежить
у `Script.html` (~5 000 рядків).

**Деплой у два місця.** `npm run push` (clasp) відправляє код в Apps Script, але
`voice.html` обслуговується окремо через GitHub Pages —
`https://mii-dev.github.io/TASKA/voice.html`. Змінив `voice.html` → потрібен ще
й `git push`, інакше сторінка лишиться старою. Clasp копіює `voice.html` у
проєкт Apps Script, але та копія не використовується.

**`npm run push` оновлює лише HEAD.** Робоче посилання прив'язане до версії —
щоб зміни туди дійшли, треба `npx clasp deploy -i <deploymentId>`.

## Пастки, на яких уже обпікались

**Дати.** У таблиці вони зберігаються як `Date` (локальна північ), а клієнт
надсилає `"YYYY-MM-DD"`. `toISOString()` на такій даті зсуває день назад у Києві.
Для порівняння дат — `toCalendarDateKey()`, для запису в аркуш — `buildSheetRow()`
(інакше комірка назавжди стає текстом і ламає сортування).

**Мікрофон в Apps Script не працює.** Сторінка рендериться у вкладеному iframe
без `microphone` у Permissions-Policy, тож `SpeechRecognition` завжди дає
`not-allowed` — і на десктопі, і на телефоні. Саме тому розпізнавання винесене на
GitHub Pages і повертає текст через `postMessage`.

**Екранування обов'язкове при рендері.** `escapeHtml()` для тексту,
`escapeJsArg()` для аргументів `onclick` (звичайного HTML-екранування там мало —
парсер розкодує `&#39;` назад в апостроф і зламає обробник), `safeUrl()` для
`href`. Назви подій календаря контролює будь-хто, хто надішле запрошення.

**Не вживай `alert()`** — він морозить сторінку в Safari на iOS. Є `showToast()`.

## Асистент (Gemini)

Модель повертає `{text, actions:[{action, data}]}`. Дії із задачами
(`createTask`/`updateTask`/`deleteTask`/`decomposeTask`) показують картку
підтвердження, **а `createEvent` виконується одразу, без підтвердження** — так
свідомо попросив власник. Тому валідація для подій робиться на сервері
(`resolveEventTimes`), а не покладається на око користувача.

Дані з ClickUp пишуть інші люди, тому в контексті вони обгорнуті маркерами
`<<<CLICKUP_DANI>>>`, і системна інструкція каже сприймати їх як дані, а не
команди. Новий недовірений вміст проводь через `untrustedText()`.

Контекст асистента кешується на 60 с. Будь-який запис, що змінює побачене
асистентом, має викликати `invalidateAiContextCache()` — включно з контактами,
які теж входять у контекст.

## Стиль

Пріоритет власника — мінімум дій: краще виконати одразу й дати легко виправити,
ніж перепитувати. Підтвердження лишаємо тільки там, де відкотити важко.
